Throttler:
ритм для целого batch

Небольшой stage между Reader и consumer: он принимает готовый пакет транзакций, при необходимости ждёт и передаёт этот же пакет дальше.

Фактическое состояние на основе технического разбора T0092 и текущего исходного кода. Это не проект изменения алгоритма.

Что важно знать владельцу

Throttler не делит пакет на отдельные транзакции. В обычном режиме он рассчитывает паузу для всего batch, затем делает handoff в Sender channel. Поэтому крупный batch означает заметную паузу перед первой отправкой.

📦

Единица работы

На входе и выходе остаётся один и тот же []Transaction. Внутри Throttler batch не дробится.

⏱️

Ограничение TPS

В installed пауза равна размеру batch, делённому на запрошенный TPS.

🧭

Управление

Обновления настроек и отмена context прерывают ожидание и переопределяют дальнейшее действие.

Поток данных и ответственность

У каждого канала есть один создатель и закрывающая goroutine. Throttler — единственный stage между Reader channel и Sender channel.

Почему первая отправка может ждать 250 секунд

В режиме installed вычисление относится к целому batch. Время начинается с приёма batch и не является постепенной выдачей транзакций по одной.

len(batch) × 1 sразмер одного принятого пакета
÷
requested TPSзапрошенный темп транзакций в секунду
50 000 ÷ 200 = 250 s

Текущие defaults: read batch size 50 000 и requested TPS 200. Это примерно 4 мин 10 с до первой отправки целого batch.

50 000 ÷ 150 ≈ 333 s

При том же batch и TPS 150 ожидание составит около 5 мин 33 с.

Меньше batch → меньше пауза

Формула линейна по размеру batch: Throttler использует длину реально принятого пакета.

Три условия, которые меняют ожидание

🟢 installed + TPS > 0

Throttler рассчитывает len(batch) / requestedTPS и ждёт оставшееся время интервала перед отправкой.

⚡ bypass

Расчёт и ожидание по TPS пропускаются. Batch передаётся, как только Sender channel готов принять его.

⏸️ Pause

Consumer отменяется и event loop подтверждённо отправляет Throttler update с paused: true. Producer и Throttler не отменяются; ещё не отправленный batch удерживается.

0️⃣ installed + TPS = 0

Принятый batch не получает интервал отправки и ждёт только обновления settings либо отмены context. Это не режим bypass.

📊 Разные границы метрик

readerChannel.recordReceive фиксируется после приёма Throttler из Reader channel, а senderChannel.recordReceive — после приёма Consumer из Sender channel.

Run, Pause, Resume и Reset

Жизненный цикл отделён от передачи batch. Resume использует уже существующие Producer и Throttler; Reset из paused завершает старую цепочку и возвращает систему в idle.

Короткие фрагменты и ссылки на текущий код

Ниже — опорные места реализации. Ссылки относительные: отчёт открывается локально и не требует сети.

throttler.go · interval / pause / zero TPS
if settings.paused ||
  (settings.mode == throttlerInstalled &&
   settings.requestedTPS == 0) {
  // ждать отмены или update settings
}

if settings.mode == throttlerInstalled {
  interval := time.Duration(len(batch)) * time.Second /
    time.Duration(settings.requestedTPS)
}
