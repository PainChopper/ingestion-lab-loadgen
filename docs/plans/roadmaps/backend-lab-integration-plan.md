# План оживления лаборатории на Go-backend

Статус: согласован с Виталёсом, реализация впереди.

## Цель

Подключить существующую визуальную лабораторию к настоящему Go pipeline: Reader → канал → Throttler → канал → Sender → HTTP target. Управление в UI должно менять реальную нагрузку, а показатели и анимация — отражать измерения backend.

Рабочий repository: `ingestion-lab-loadgen-public-prep`. Frontend находится в `frontend/`.

## Исходное состояние

На момент составления плана Go читает Parquet и считает обработанные транзакции. Pipeline запускается при старте процесса. HTTP handler принимает команды Run, Pause и Reset, но основной loop ещё не применяет их. Throttler не подключён к pipeline; настоящего HTTP Sender нет.

`HttpAdapter` запрашивает snapshot с четырьмя полями: `runState`, `totalTransactions`, `readerWorkers`, `senderWorkers`. Остальные показатели frontend пока заполняет заглушками. Simulation реализует работающую визуальную модель и служит ориентиром поведения.

## Общие решения

- Frontend запрашивает snapshot, Go возвращает согласованное состояние. По мере реализации расширяется содержимое ответа; смена транспорта не требуется.
- В каждом срезе новые данные и команды сразу подключаются через `HttpAdapter` к существующему UI.
- Неизмеренные показатели остаются недоступными. Максимальная производительность Reader не переносится из simulation как якобы измеренное значение.
- Simulation сохраняется отдельным рабочим режимом.
- Реализацию Go и необходимых изменений frontend выполняют агенты; Виталёс принимает поведение.
- Этот файл хранит общий порядок срезов. Каждый исполняемый срез получает отдельный файл плана в `docs/plans/current/`; после завершения его файл перемещается в `docs/plans/archive/`.
- Проверки входят в выполнение срезов и не выделяются в самостоятельные пункты этого плана.

## Заметки для последующего разбора

- **Копирование остатка при сборке batch.** В [производителе batch-ей](../../../producer.go#L42-L45) `append` может сначала увеличить аккумулятор и скопировать его содержимое, а после отправки batch остаток копируется ещё раз в новый слайс. Позже разобрать вариант, который заполняет текущий batch только до границы и переносит оставшиеся строки сразу в следующий. Для полного отказа от копирования отдельно продумать владение буферами между reader и consumer. Сначала измерить стоимость текущего решения; сейчас код не менять.

```go
if n > 0 {
	accumulator = append(accumulator, rows[:n]...)
	if len(accumulator) >= batchSize {
		batches <- accumulator[:batchSize]
		accumulator = append(make([]Transaction, 0, batchSize), accumulator[batchSize:]...)
	}
}
```
